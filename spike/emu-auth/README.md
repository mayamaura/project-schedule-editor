# EMU 認証の確認（Phase 0 / S0-4）

**目的:** 利用予定の GitHub（EMU を含む）で、ブラウザ認証（Git Credential Manager）による clone / push が通るかを、実環境で早期に確認する（要件 F-508）。結果で、代替認証（Device Flow / PAT）への切替が必要かが分かる。

## 1. あなたの環境で実行する（約5分）

```
node spike/emu-auth/check.mjs https://<ホスト>/<組織>/<リポジトリ>.git
```

- 利用する GitHub のリポジトリ（データ用リポジトリ）の HTTPS URL を渡す。
- 認証が必要なら**ブラウザが開く**。サインイン（SSO を含む）すると続行する。
- 最後に表示される「報告用」の JSON（秘密情報なし）を貼り付けて共有してください。
- スクリプトは `git config` を変更しない。失敗時に必要な設定は案内だけ表示する。

## 2. 管理者に確認する項目（EMU の場合）

| 確認項目 | なぜ必要か |
|---|---|
| 接続先ホスト（`github.com` / `<サブドメイン>.ghe.com`） | アプリの接続先設定と、GCM の設定（`ghe.com` は provider 指定が必要な場合がある） |
| SAML SSO の有無と、トークンの組織への承認手順 | 認証後に `repository not found` になる原因の代表例 |
| OAuth App / GitHub App を**組織内で登録し、承認できるか** | Device Flow（代替認証）に必要 |
| Copilot の契約・ポリシー（CLI / SDK の利用が許可されているか） | AI 機能（R4）の前提 |
| データ用リポジトリへの書き込み権限（push できるか） | 保存・反映の前提 |

## 3. 結果に応じた判断

| 結果 | 次の対応 |
|---|---|
| 成功 | GCM のブラウザ認証を第一候補にする方針のまま進める |
| ホスト設定が必要 | アプリの設定にホスト名を持たせ、必要なら provider 設定を案内する（F-508） |
| 失敗（SSO・承認の問題） | 管理者に確認。難しければ代替認証（Device Flow / PAT）を優先して実装する |
