# 機能実装の手順（引数: 要件ID または機能名）

1. **仕様確認**: requirements.html で該当要件を読む。関連する data-model / ui-design / architecture / git-ux の記述も読む。依存する open-questions に未決の★があれば停止してユーザーに確認。
2. **設計メモ**（短く）: どの層（domain / main / renderer）に何を置くか、新規の型・コマンド・IPC、影響する既存コードを書き出す。レイヤ制約（CLAUDE.md）に違反しないか確認。
3. **テスト先行**:
   - domain: 失敗する Vitest テストを先に書く（正常系・境界・不正入力）。テスト名/先頭コメントに `@req F-xxx`。
   - UI 操作は、可能な限りロジックを domain に寄せてそこでテストする。主要フローのみ E2E。
4. **実装**: 最小の変更で。実装側にも `@req F-xxx` を付ける。ドラッグ等は rAF + 確定時 1 コマンド。
5. **性能**: 描画・イベントに関わる場合、25,000 イベントで確認する。
6. **ドキュメント同期**: 実装中に仕様の不足・変更が出たら `/spec-change` の手順で文書を更新（コードだけ変えて終わらない）。
7. **検証**: `node scripts/verify.mjs` が全て通ること。`node scripts/trace.mjs --report` で当該要件に実装・テストのタグが付いたことを確認。
8. **報告**: 変更ファイル、通ったチェック、残課題、追加した要件/決定を簡潔に。コミットはユーザーの依頼があったときだけ。
