概要要件定義データモデルアーキテクチャ・技術選定UI設計Git連携・UX未決事項・追加定義

要件定義

優先度: M=必須(MVP) / S=重要(次段階) / C=任意。依頼文から読み取れたものに加え、必要と思われるものを「提案」として記載（要判断）。

1. 機能要件

1.1 スケジュール表示

ID要件優先備考
F-101左に プロジェクトツリー（名称・列）、右に 日付軸のタイムラインを持つ Excel ライクな2ペイン表示M縦横スクロール同期、ヘッダ固定
F-1021行に複数のイベント（バー）とマイルストーン（◆）を表示M同一行で重なる場合の扱い（F-103）
F-103同一行でイベントが重なった場合、サブレーン展開（行高が自動で増える）または重ね表示を選べるS要判断: 既定の挙動
F-104ズーム切替（日/週/月/四半期/年）、今日線、週末・祝日の背景表示M
F-105プロジェクト階層の展開/折りたたみ。折りたたみ時、親行に子の期間を集約表示（サマリーバー）M集約は自動計算か手動か要判断
F-106イベント/マイルストーンに 色・ラベル・種別（フェーズ、リリース等）を設定M種別マスタは設定で編集可能
F-107多数行（500行程度）・数年範囲でも滑らかにスクロールM仮想化必須（NF-001）

ID要件優先備考
F-201バーのドラッグで移動、端のドラッグで開始/終了日変更。◆のドラッグで日付変更M日単位スナップ
F-202空白セルのダブルクリック/ドラッグでイベント作成、◆作成M
F-203セル選択・矢印キー移動・コピー&ペースト・Delete など Excel 風のキーボード操作S範囲選択の意味（日付範囲→イベント化？）要判断
F-204詳細パネルで 名称・日付・メモ・担当・状態 を数値/日付入力で編集M
F-205プロジェクトの追加・削除・並べ替え・親子付け替え（ドラッグ&ドロップ）M

1.3 階層・依存関係

ID要件優先備考
F-301プロジェクトは任意深さの親子構造を持つM深さ上限の目安を決める
F-302依存関係を 矢印線で表示。端点はプロジェクト/イベント/マイルストーンのいずれか（要判断）M端点粒度は設計に大きく影響 → 未決事項
F-303依存タイプ: FS / SS / FF / SF とラグ(日数)SMVP は FS のみでも可
F-304依存線の表示切替: 全表示 / 選択項目に関係するもののみ / 非表示 / 種別・階層で絞込M依頼の要件
F-305依存違反（後続が先行より前）の警告表示S自動再スケジュールするかは要判断
F-306選択項目の上流/下流（影響範囲）をハイライトS影響調査に有用

1.5 Git 連携（詳細は Git連携・UX）

ID要件優先備考
F-501データリポジトリの 新規作成 / clone / 既存フォルダを開くM初回セットアップウィザード
F-502「変更を保存」（= commit）。変更内容を日本語で要約表示（例:「A案件のリリース日を 3/1→3/15」）M差分は JSON でなく業務語で見せる
F-503「共有する」（= pull + push）を1ボタンで。失敗時は平易な説明と選択肢M
F-504履歴一覧、過去時点の閲覧（読み取り専用）、特定版に戻す（新しい変更として）M履歴を書き換える操作は出さない
F-5052つの版の比較（どの日程がどう動いたかをタイムライン上で差分表示）S本アプリの大きな価値。仕組みは データモデル 4.5
F-509日程変更の検出: 両版の JSON をパースし ID 単位で比較し、追加/削除/日付変更(日数差)/親子移動/属性/依存の変更を抽出するMF-502, 503, 505, 506 の共通基盤
F-510履歴の各コミットに変更要約を表示。「後ろ倒しになった項目」の一覧（変動日数順）、期間・プロジェクト・作者での絞込S
F-511共有時、取り込む他者の変更を取り込み前に一覧表示M
F-512変更による依存違反の新規発生を警告として表示SF-305 と連動
F-506競合解決UI（項目単位で「自分の/相手の」を選ぶ）M最大のUX課題
F-507ブランチ相当の「シナリオ（案）」機能: 別案を作って比較・採用C用語は「案」。後回し可
F-508リモート認証（HTTPS トークン / SSH）設定の支援MOS資格情報ストア利用

2. 非機能要件

ID要件目標（案）
NF-001性能500行×5年・イベント5,000件で 60fps に近いスクロール、ドラッグ中の遅延 <16ms 目標
NF-002対応OSWindows 10/11 必須、macOS 任意（要判断）
NF-003オフライン編集・commit はオフライン可。共有時のみネット必要
NF-004データ安全性クラッシュ時も未保存編集を復元（自動一時保存）。Git操作は破壊的操作（force push, reset --hard）を提供しない
NF-005マージしやすさ同時編集の衝突が最小になるデータ形式（データモデル）
NF-006スキーマ互換スキーマバージョン付き。旧版データの自動マイグレーション。新しいデータを旧アプリが壊さない
NF-007セキュリティElectron: contextIsolation 有効、nodeIntegration 無効、preload 経由のIPCのみ。認証情報は OS 資格情報ストア
NF-008配布インストーラ(NSIS等)、コード署名、自動更新（要判断）。Git同梱によりユーザーに Git インストール不要
NF-009国際化日本語UI優先。文言は外出し（将来の多言語化余地）
NF-010アクセシビリティキーボードのみで主要操作可能。色だけに依存しない表示（形・パターン）
NF-011テストドメインロジック（日付計算・依存検証・差分）は単体テスト必須。E2E は主要フローのみ
非機能要件の追記。
